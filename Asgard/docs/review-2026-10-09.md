# Independent review of Baldur's calibration and AI-assisted method (2026-10-09)

One review by an agent with no part in writing the code, of branch `claude/baldur-estimation` at
`eeb8e1d`. Every finding is proven with a script it ran. Ysildir, built afterwards, was left out;
its own guarantees are tested in `tests/test_ysildir.py`.

| Severity | Confirmed | Worst |
| --- | --- | --- |
| Blocker | 3 | Taking the AI figures, or a calibration, could push time up: `approve --ai --set` approved 2h45m on a 2h00m day; Jira ended at 2h45m when a lowered ticket's time was already in Jira; calibration accepted a lead-in that estimates high on every day it could measure |
| Should fix | 7 | `approve --ai` took figures nobody was shown, and stored reviews unchecked; the Kiro guard missed eleven realistic commands, one of which approved a day |

Every confirmed finding is fixed. Each fix has a regression test named after its id:
- `tests/test_baldur_assist.py`, in `ReviewFindingsTests` and `AgentGuardTests.test_r6_*`;
- `tests/test_baldur_calibrate.py`, in `ReviewFindingsTests`.

The reviewer's scripts were re-run against the fixed code, and all 16 pass. Ten were adapted first, to the new `approve --ai ID` or to the shape of the fix; the adaptations are below. The scripts aren't kept in the repo. Results on Linux (Python 3.11.15, SQLite 3.45.1), recorded in HANDOFF: the full suite on Python 3.11 with and without the MCP SDK and on 3.9, the schema check, vermin, ruff, and `baldur_smoke.sh` (still PROJ-42 1h30m, PROJ-51 30m).

## Behaviour people see

- **Taking AI figures:** `baldur.cmd approve --date D --ai ID`, with the id from `ai show`, the day report or Ysildir. Guides, the README and Ysildir's `take` carry it.
- **What gets posted:** `ai show` and the day report list each ticket's `Reviewed:` line, word for word.
- **Your own figures:** taking a ticket the AI raised while keeping the time on the one it lowered is refused.
- **Time already in Jira:** it never moves, and the review pack tells the AI so (`in_jira`, prompt `baldur-review-3`).
- **Calibration:** it lists the days it leaves out, writes `baldur.json` only under Muninn's lock, and notes real ticket hours only for your projects.
- **Agents:** a name is one word, and summaries refuse code lines and control characters.
- **The Kiro guard:** it also blocks `baldur.json` and other databases in Asgard's folder. It reads quoted commands, but not commit messages or summaries.

## Adapted scripts

These scripts were changed to run against the fixed code:

- **R2, R4, R7, R11 and R15** pass the id of the figures shown (R4's fix); R4 and R7 get it from `ai show --json`.
- **R2 expects no AI figures:** with all of PROJ-42's time in Jira, `approve --ai` finds none to take.
- **R6 expects refusals.** It expects argparse to refuse `--acc`, and runs its command only when the hook allows it (the original ran it regardless).
- **R9 expects the code summaries to be refused.** It also checks that a summary stored earlier, with an escape, prints clean.
- **R12 waits three seconds instead.** The original waited for each run to write `baldur.json` while the lock was held, which never happens now. The new version checks that the file is untouched until the lock is released, then that the two runs agree.
- **R14 checks the fix as built.** The changed report must stop counting, and integrity must report it; the original asked that the citations can't change at all.
- **R16 expects the keys to be refused.**
